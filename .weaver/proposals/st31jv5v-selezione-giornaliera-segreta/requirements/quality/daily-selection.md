# Daily selection reliability

## daily-word

- Verify deterministic vocabulary normalization, fingerprint and unchanged actual 7,679-entry membership from pinned inputs. AUDIO, OZONO and representative inflections, Italian-use loanwords and uncommon terms remain eligible as both guesses and solutions. Test actual admission behavior rather than re-pin a removed permutation or merely assert list sizes.
- Verify Rome midnight, both DST changes, different device time zones, reopening after missed boundaries, and a visible tab crossing a day while selection is delayed. Historical v1 dates before 2026-11-08 stay unchanged; activation retires the old public game exactly once, with no second reset on 2026-11-09. Existing old-schedule migration tests must adopt the new agreed boundary without preserving obsolete future-permutation assertions.
- Exercise valid selection, HTTP failure, absent data, malformed JSON, unsupported schema, impossible or wrong date, wrong vocabulary, invalid index and inconsistent challenge identity. They must never create a fallback game, consume attempts, start time or add an outcome. A valid retained current-day record survives failure; after midnight it no longer authorizes play.
- Verify restore after refresh with a partly entered positional draft, committed rows, locked autocomplete and terminal result. Preserve historical scores and preferences. Verify concurrent tabs and repeated migration cannot erase acquired progress, double-count results or restore a stale public-calendar activation record.
- Exercise delayed and out-of-order acquisitions, an obsolete response after midnight, duplicate manual retries, storage events while loading and date changes before applying a fetched record. No late response may replace a newer assignment or create an obsolete game. A conflicting same-date response cannot reset a retained valid game.
- Browser verification must use the production-built site under `/ParoleCompetitive/` with controlled dates and intercepted public-data responses. Observe initial loading, failure, manual Riprova, successful acquisition, same-day reload/offline restoration, an unpublished new day, and later manual recovery. Verify actual disabled keyboard and blank board while unavailable, accessible status, retained modal/focus and historical statistics, no obsolete recap/share, and successful play after acquisition. Preserve existing reveal, reduced-motion, autocomplete, scoring and spoiler-free behavior. No cold-start offline claim.

## daily-publication

- Check HMAC selection against independently known vectors with a nonsecret test key, including leading-zero digest bytes and integer values beyond Number precision. Verify canonical message bytes, modulo boundaries, stable output for repeated runs and the unchanged vocabulary order. Never use the live secret in PR tests, fixtures or recorded output.
- Verify absent-record creation and same-day rerun behavior, including changed key or deploying vocabulary: an already fixed assignment is reused exactly or deployment is blocked, never silently replaced. Exercise a durable write followed by deployment failure and recovery, missing secret with and without an existing record, and missed dates without invented backfill.
- Verify serialization across scheduled, main-release and manual requests. A stale queued source revision, a newer main change during verification, or a run crossing midnight cannot promote stale code or an earlier record as current. Validate the complete artifact's client vocabulary and public selection before promotion; keep the last successful live deployment on failure.
- Verify the final Pages artifact, browser bundle, public record, durable data branch, logs and uploaded artifacts contain no production key, equivalent seed or future selection sequence. Secret access is limited to the trusted generation step and never available to PR code or the frontend build. Current answers and already published historical records are intentionally public, not anti-cheat protected.
- Document the actual GitHub schedule limits: delayed or dropped execution, default-branch-only execution and automatic disabling in public repositories after 60 inactive days. Verify the configured IANA timezone and date handling across DST without claiming an exact run time. Recovery is an authorized manual dispatch, not a hidden timer or repeated retry.
- During implementation, prove the public production-prefixed data path and a same-day idempotent recovery using the authorized workflow, without showing the key. Report deployment URL, observed record/date/identity and exercised checks accurately; missing GitHub permissions are an actionable blocker, not a fabricated successful deployment.
